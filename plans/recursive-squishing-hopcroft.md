# 执行过程折叠标题：显示工具实际所做的事

## Context
Agent 执行过程模块（`ExecutionProcess`，`src/app/App.tsx`）的可折叠标题目前是固定文案：
- 完成态硬编码为「显示执行意图」
- 执行中态用 `preset.running`（如「正在生成 PPT」）

用户反馈：标题不应是固定的「执行意图」文案，而应描述**调用这一批工具是在做什么事**（对工具批次工作的概括），且完成态也要保持这种描述性文案，而不是「显示执行意图」/「任务已完成」。

## 目标
把折叠标题改成每个流程阶段一句「概括本批工具做了什么」的描述性文案，执行中与完成态都用它。

## 改动

### 1. 给每个 preset 增加描述性标题文案
文件：`src/app/App.tsx`，`PROCESS_PRESETS`（约 1052–1091 行）。
为每个 variant 增加一个字段（复用现有 `running`，或新增 `intent`）描述工具批次所做的事，例如：
- `requirement`：检索并分析主题资料，梳理制作需求
- `outline`：拆解需求逻辑，编排大纲结构
- `ppt`：撰写各页内容并渲染 PPT 页面

（最终文案以用户确认为准，见下方问题。）

### 2. 折叠标题统一使用该文案
文件：`src/app/App.tsx`，`ExecutionProcess`。
- 完成态（约 1132 行）：把 `显示执行意图` 替换为 `preset.<该字段>`。
- 执行中态（约 1144 行）：`preset.running` 替换为同一字段（若沿用 `running` 则无需改动）。

### 3. 顺带修复相邻类名拼接错误
第 1142 行 `font-normaltext-[rgba(0,0,0,0.88)]` 被错误拼接，应为 `font-normal text-[rgba(0,0,0,0.88)]`。

## 验证
- 预览界面触发「PPT生成」流程，分别在需求 / 大纲 / PPT 三个阶段查看：
  - 执行中折叠标题显示对应的描述性文案。
  - 执行完成后标题仍是该描述性文案，而非「显示执行意图」或「任务已完成」。
- 展开/折叠 chevron 方向正常，工具行样式不变。
