# AI Agent 执行过程交互文档

## 1. 文档目标

本文档用于定义 AI Chat 产品中“AI 回复前执行过程”的交互结构、信息层级、展示规则与文案原则，供产品、设计、开发协同使用。

本文档聚焦：

- Agent 卡片的交互结构
- 卡片内信息槽位规则
- 工具动作项展示规则
- 动作语义分类与文案原则
- 显隐、排序、覆盖规则

## 2. 设计目标

### 2.1 用户目标

让用户理解：

- 当前 AI 在帮我解决什么问题
- 目前推进到了什么程度
- 系统通过哪些动作在推进
- 如果出现异常，系统正在如何恢复

### 2.2 设计原则

- 展示任务推进，不展示底层系统架构
- 标题讲“解决什么”，内容讲“怎么解决”
- icon 表示动作类别，文字表示当前状态或结果
- 工具名不直接展示给用户
- 有数据则显示，无数据则隐藏
- 同一动作类别仅保留最新状态

## 3. 整体信息结构

执行过程由任务级内容流与多个 Agent 卡片共同组成。

### 3.1 任务执行流结构

任务执行流由以下几部分组成：

- 卡片前信息槽位
- Agent 卡片
- 卡片后结果槽位

整体表现为一条按执行过程推进的内容流。

### 3.2 任务级信息槽位

除 Agent 卡片外，任务执行流中还可插入以下信息槽位：

- 任务目标
用于说明当前整个任务在解决什么问题
- 卡片前信息
用于说明进入某个 Agent 前的前置状态、前置结论或前置结果
- 卡片后信息
用于说明一个 Agent 处理完成后，到下一个 Agent 介入前的阶段结果、中间结论、过程衔接信息，或当前任务范围内的阶段性总结、总结结果或全局结果


说明：

- 任务级信息槽位有数据则显示，无数据则不显示
- 任务级信息槽位可多次出现
- 任务级信息槽位按执行过程动态插入，不采用固定位置模板

- 每张卡片 = 一个 Agent 处理单元
- 每张卡片只表达一个 Agent 当前负责解决的一类问题
- 卡片内包含若干可选信息槽位

## 4. Agent 卡片定义

### 4.1 卡片定位

每张卡片代表一个 Agent 处理单元，用来展示该 Agent 当前在帮用户解决什么问题，以及它的阶段进展。

### 4.2 卡片结构

每张卡片可包含以下信息：

- 卡片标题
说明该 Agent 在解决什么问题
- 阶段结果
说明当前阶段已经得到的结果
- 中间结论
说明对当前结果的归纳或总结
- 工具动作
说明通过哪些动作推进到了当前结果

### 4.3 卡片标题规则

卡片标题用于展示该 Agent 在帮用户解决什么问题。

标题规则：

- 不展示 Agent 名称
- 不展示内部角色名
- 不写“正在做什么”
- 聚焦“解决什么问题”

例如：

- 查找与你问题最相关的资料
- 从结果中提取可用信息
- 整理成可直接发送的邮件草稿
- 检查答案中的冲突内容

### 4.4 任务执行流展开/收起规则

- 任务执行中，任务执行流默认展开
- 展开状态下，用户可直接看到整个任务的执行过程
- 任务执行完成后，整体流程自动收起
- 收起后保留任务级入口，便于用户回看整个任务的执行过程
- 如需查看已完成任务的详细过程，用户可手动再次展开

### 4.5 任务执行流入口规则

- 任务执行中不单独显示入口，执行过程直接展开展示
- 任务执行完成后，整体流程自动收起，显示入口“执行过程”
- 用户点击“执行过程”后，可再次展开查看完整流程
- 如果用户在任务执行过程中主动中断流程，整体流程仍保持收起状态
- 中断态入口名称显示为“已停止执行”
- 中断态入口下方显示说明文案“你已停止本次生成回答”

## 5. 卡片内信息槽位规则

### 5.1 槽位显隐规则

- 有数据则显示
- 无数据则不显示
- 不为占位而保留空白区域

### 5.2 槽位插入规则

除卡片标题外，卡片内其他内容不采用固定顺序，而是按执行过程动态插入。

说明：

- 工具动作可连续出现
- 阶段结果可出现在任意工具动作之后
- 中间结论可出现在一组工具动作之后，也可出现在卡片末尾
- 卡片内容整体表现为一个按执行过程推进的内容流

例如：

- 工具动作
- 工具动作
- 阶段结果
- 工具动作
- 阶段结果
- 工具动作
- 中间结论

### 5.3 阶段结果

阶段结果用于表达：

- 当前阶段已经得到了什么
- 当前阶段输出了什么结果

阶段结果可在同一张卡片内多次出现。

例如：

- 找到 8 条相关结果
- 提取 5 个关键点
- 生成一版可直接编辑的答案草稿

### 5.4 中间结论

中间结论用于表达：

- 当前阶段的整理结论
- 对结果的归纳或总结

中间结论可在同一张卡片内多次出现。

例如：

- 结果主要集中在 3 个方向
- 当前资料已足够支撑第一版回答
- 冲突内容已缩小到 2 个候选项

## 6. 工具动作项定义

### 6.1 工具动作项结构

每一条工具动作项由两部分组成：

- `icon`
- `文案`

说明：

- icon 表示动作语义类别
- 文案表示当前动作的最新状态、结果或异常恢复
- 不直接展示底层工具名称

### 6.2 工具动作项信息组成

| 信息项 | 说明 |
|---|---|
| 动作语义分类 | 对应 icon 分类 |
| 展示文案 | 面向用户的状态、结果或异常恢复文案 |
| 当前状态 | 用于区分进行中、已完成、异常恢复中 |
| 最近更新时间 | 用于工具动作列表排序 |
| 来源类型 | 可选，如知识库、网页、上传文件 |

### 6.3 动作状态类型

| 状态类型 | 说明 |
|---|---|
| 进行中 | 当前动作正在处理 |
| 已完成 | 当前动作已经完成并产生结果 |
| 异常恢复中 | 当前动作出现问题，系统正在恢复 |
| 失败终态 | 当前动作经过恢复后仍未得到可用结果，需进入后续处理 |

说明：

- 前台是否显式展示状态标签，可由产品决定
- 即使不显式展示，文案也需要隐含状态信息

## 7. 工具动作项排序与覆盖规则

### 7.1 排序规则

工具动作项按工具调用时间顺序展示。

- 先调用的在前
- 后调用的在后

### 7.2 覆盖规则

同一动作语义类别如果发生多次状态更新：

- 仅保留最新状态
- 旧状态不展示

例如：

搜索动作曾先后产生：

- 正在搜索相关信息
- 找到 8 条相关结果
- 搜索结果不够精确，正在重新筛选

最终仅保留当前最新一条。

### 7.3 工具调用项与状态规则

- 一个 Agent 可同时展示多个工具调用项
- 多个工具调用项按工具调用时间顺序展示
- 每个工具调用项仅展示当前最新状态
- 同一工具调用项的旧状态不保留展示

## 8. 动作语义分类

### 8.1 分类目的

动作语义分类用于：

- 统一 icon 体系
- 统一文案模板
- 屏蔽底层工具差异

### 8.2 分类列表

| 动作语义 | 对用户的含义 |
|---|---|
| 搜索 | 去找信息、找资料、找记录 |
| 读取 | 打开并读取已有内容 |
| 提取 | 从内容里抽取字段、重点或片段 |
| 分析 | 对内容做判断、比较、归纳 |
| 生成 | 组织成可输出内容 |
| 校验 | 检查结果是否正确、完整、一致 |
| 汇总 | 合并多个结果并形成统一输出 |
| 执行 | 对外部对象执行真实操作 |

## 9. 动作语义展示规范

### 9.1 文案原则

所有动作文案尽量同时包含：

- 动作
- 对象

即：

`系统正在对什么做什么`

### 9.2 文案模板

#### 执行中

- 正在`{动作}``{对象}`
- 正在从`{对象}`中`{动作}`
- 正在对`{对象}`进行`{动作}`

#### 完成后

- 已从`{对象}`中获得`{结果}`
- 已完成`{对象}`的`{动作}`
- 已将`{对象}`处理为`{结果}`

#### 异常时

- `{对象}`当前无法完成`{动作}`，正在`{恢复动作}`
- `{对象}`的`{动作}`结果不足，正在`{补救动作}`
- `{对象}`在`{动作}`过程中出现问题，正在`{恢复动作}`

## 11. icon 设计规则

- icon 对应动作语义分类，不对应底层工具名
- 同一动作语义分类使用统一 icon
- 同一 icon 可搭配不同状态文案

例如：

- 搜索 icon + 找到 3 条相关结果
- 搜索 icon + 搜索结果不够精确，正在重新筛选
- 执行 icon + 邮件已发送给目标联系人

## 12. 最终规则摘要

- 每张卡片代表一个 Agent
- 卡片标题展示“解决什么问题”
- 卡片内槽位有数据则显示，无数据则隐藏
- 工具动作项使用 icon + 文案展示
- icon 表示动作语义，文案表示最新状态
- 同一动作类别只保留最新状态
- 工具动作项按工具调用时间排序
- 所有过程文案尽量同时包含“动作 + 对象”
